# AI Agent 学习大纲

> 目标：面向秋招 Agent 开发 / AI 应用开发岗，建立 **原理 → 设计 → 工程落地 → 稳定性与排障** 的完整能力。
> 面试中能做到：讲清 Agent 怎么工作，能设计一个生产级 Agent 系统，能回答"出错了怎么办、怎么保证稳定、轨迹太长怎么查"，并能结合项目深挖。
>
> 状态说明：`未开始` / `学习中` / `已学习` / `已复习`

## 大纲依据（2026-10 调研）

调研了 2026 年的 Agent 岗面经与题库（面灵 AI 155 题、字节 Agent 开发四面、字节番茄小说 Agent 实习一面、知乎三 offer 复盘、小林/卡码/JavaGuide 题库等），结论：

- **八股层**（ReAct、FC、MCP、RAG、记忆）是必答题，但只占一部分。
- **工程层占比明显上升**：Harness / Agent Loop 设计、稳定性与容错、可观测与轨迹排查、评估、安全，几乎每场都会问，工程向岗位尤其看重。
- **项目深挖非常细**：追问会具体到"tool_call_id 怎么配对""子 Agent 递归怎么防止 Token 爆掉""优化提升了多少、怎么测的"。
- **手撕代码**：ReAct 循环、死循环检测器、带退避的重试、DAG 拓扑调度，另外每轮还有一道 LeetCode medium。

## 第一阶段：基础

### 1. LLM 基础

**状态：已学习**

- Transformer、QKV、多头注意力，为什么除以 √d_k，O(n²) 瓶颈
- Token、上下文窗口、KV Cache、上下文腐化（Context Rot）
- 采样参数：temperature、top_p
- 预训练 / SFT / RLHF；推理模型；微调和 RAG 怎么选
- 幻觉是怎么产生的

### 2. Prompt 与结构化输出

**状态：未开始**

- System / Few-shot / CoT 的作用；为什么换个说法效果能差十倍
- Structured Output / JSON Schema：如何保证输出可解析，解析失败怎么办
- Prompt / Context / Harness Engineering 三者的区别

## 第二阶段：Agent 核心

### 3. 工具调用：Function Calling / MCP / Skills

**状态：未开始**

- Function Calling 完整链路；tool_call_id 配对；并行工具调用
- 工具描述和参数 Schema 怎么设计；工具太多怎么办（按角色/任务裁剪、按需加载）
- MCP：架构、Tools/Resources/Prompts、传输方式；MCP 是否等于远程调用
- FC、MCP、Skills 三者的区别与协作；A2A 和 MCP 的关系
- 工具返回过大（如 DOM、大文件）：截断、分页、清洗

### 4. Agent 范式与 Workflow 编排

**状态：未开始**

- Agent 与 Workflow 的区别，什么时候不该用 Agent
- ReAct、Plan-and-Execute、Reflection、ToT 的选型与实战效果
- Workflow 模式：链式、路由、并行、编排者-执行者、评估-优化
- 基于 DAG 的规划：节点设计、环检测、拓扑调度、局部重规划
- Graph 编排：节点、状态、检查点、人工审批节点

### 5. RAG

**状态：未开始**

- 完整链路：切分 → Embedding → 索引 → 检索 → 重排 → 生成
- 混合检索（BM25 + 向量）的原理与收益，HNSW
- 检索效果评估：Recall@K、MRR；怎么构建测试集
- Agentic RAG；FC 与 RAG 的区别和联系
- 内容过时和模型幻觉怎么区分

### 6. 上下文工程与记忆

**状态：未开始**

- 上下文溢出的治理：滑动窗口、摘要压缩、Auto-Compact、任务状态快照
- 目标漂移 / 上下文漂移：目标重注入、定期反思、重新规划
- 记忆分层：工作记忆 / 长期记忆 / 外部知识；写入筛选、召回、冲突与过期处理
- 记忆效果怎么量化评估
- Token 治理：预算、成本、Prompt Caching

### 7. 多智能体

**状态：未开始**

- 何时需要多 Agent；主管-子 Agent、流水线等架构
- 主/子 Agent 通信链路设计、上下文隔离、角色边界与工具权限
- 子 Agent 递归调用的控制：深度上限、全局预算、防环
- 多 Agent 消息编排与保序（thread 隔离、seq_no、parent_event_id）
- 通信失败与错误传播的兜底

## 第三阶段：生产级工程（面试重点）

### 8. Harness 工程与 Agent Loop 运行时

**状态：未开始**

- Harness 是什么，和框架有什么区别；为什么最近火了
- Agent Loop 的五类治理：上下文、状态、预算、工具、终止条件
- 状态持久化与 Checkpoint：中途异常如何断点恢复
- Human-in-the-loop：Loop 状态如何暂停、暂存、恢复
- 流式输出（SSE）、长任务异步化、分布式状态同步
- 参考 Claude Code 的设计：子 Agent、上下文压缩、外部文件记录状态

### 9. 稳定性与容错 ⭐

**状态：未开始**

- Agent 失败场景分类：工具失败、上下文溢出、目标漂移、幻觉、死循环、链式错误积累
- 长链路可靠性按步累乘（0.95^15 ≈ 46%），这是所有稳定性设计的出发点
- 工具错误分类处理：可重试（超时、限流）用指数退避；参数错误回传给模型自我修复；不可恢复的错误降级或转人工
- 超时、重试上限、幂等性（重试不能重复下单）、异常隔离
- 死循环三层防御：工具内去重 → 主循环检测重复模式 → 入口超时/预算兜底
- 降级策略：模型降级、换备用工具、退回固定 Workflow、转人工
- 工具结果为空或格式错误、输出解析失败怎么处理
- 前序步骤幻觉的链式传播：中间结果校验、Reviewer 节点

### 10. 可观测性与轨迹排查 ⭐

**状态：未开始**

- Trace 设计：每个任务一个 trace，每次 LLM 调用、工具调用、handoff 各一个 span；记录哪些字段
- 轨迹留存、回放（Replay）与重跑
- 长轨迹怎么排查：先定位第一个出错的步骤；区分是 Prompt、模型、工具还是逻辑的问题；用 LLM-as-Judge 做失败归因
- 典型排障题：线上 Agent 一直调工具不返回，怎么 Debug
- 指标体系：任务成功率、步数、Token/成本、延迟、工具错误率、人工接管率
- 告警与监控；执行过程要不要对用户透明展示，展示到什么粒度
- 工具：LangSmith / Langfuse / OpenTelemetry 思路

### 11. 评估体系

**状态：未开始**

- 评测维度：结果正确性、过程（轨迹）质量、效率、成本、安全
- 评测集构建；离线评测与线上 A/B
- LLM-as-Judge 及其可靠性问题
- 幻觉率的定义与计算；规划能力怎么衡量
- 评测闭环：bad case → 归因 → 修复 → 回归

### 12. 安全与权限

**状态：未开始**

- Prompt Injection 和间接注入（网页、文档、工具返回里的恶意指令）
- 权限控制：权限靠执行层鉴权，不能只靠 Prompt；最小权限；Agent 访问 MCP 服务的授权
- 沙箱实现；高危操作（资金、运维）的人工审批
- Key 泄露、敏感信息保护
